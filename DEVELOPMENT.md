# Development

Generated by `make development` from `config.toml`. README.md is generated by `make readme`. Neither is edited by hand.

## Requirements

| What | Which |
|---|---|
| this decompilation toolkit, as a command | `pip install -e <toolkit checkout>` for its console scripts, or the checkout's `bin/` directory on `PATH`. Importable is not enough: every goal below runs `decomp` as a command |
| MIPS cross binutils | `mips-linux-gnu-` |
| Python | 3.11 or newer, with `venv` |
| splat | `0.50.0` |

## What you supply

Nothing in this repository is game content and nothing in it is the compiler. `make bootstrap` creates both directories and writes a note into each naming what belongs there.

| What | Where you put it | Checked against |
|---|---|---|
| the cartridge image you dumped, one per cartridge you build | `artifacts/roms/{slug}.<id>.z64` | the SHA256 README.md lists for it |
| `asn64.exe`, `cc1`, `psyq-obj-parser`, `wibo` | `artifacts/toolchain` | `{toolkit}/gcc272/toolchain.sha256` |
| `acpp`, `as1`, `cc`, `cfe`, `err.english.cc`, `ugen`, `uopt` | `artifacts/toolchain` | `tools/ido/ido-7.1.sha256` |

`make setup` finds each file by name, refuses anything whose digest is not the pinned one, and installs the verified copies into `artifacts/gcc-2.7.2`, `artifacts/ido/7.1`. Nothing is downloaded.

## Goals

The Makefile here holds no build logic. It forwards each goal to the toolkit verbatim. `VERSION=<id>` picks the cartridge; without it the goal runs against whichever cartridge `[project].reference` names.

| Goal | What it does |
|---|---|
| `make bootstrap` | create the directories you fill by hand, each with a note naming what goes in it |
| `make build` | extract, compile, link, and verify the image against the cartridge |
| `make check` | judge the built tree |
| `make clean` | remove this cartridge's build products |
| `make decomp-yaml` | rewrite the split description |
| `make development` | rewrite this file |
| `make distclean` | remove everything under the artifacts tree except what you supplied |
| `make progress` | draw the measurement |
| `make readme` | rewrite README.md |
| `make report` | write the tracker report |
| `make setup` | verify the compiler, the cross binutils, Python and splat, then install the verified compiler |
| `make test` | the project's own controls |
| `make versions` | list the cartridges this project declares |

## The standard of proof

A byte-identical cartridge and nothing else. `make` relinks the image and compares every one of its 8,388,608 bytes against the digest `config.toml` pins for that cartridge.

```text
OK(rom-identity): the rebuilt image is cartridge 'us', all 8388608 bytes
```

Nothing lands on a function count, a percentage, or a reviewer's judgement that the C reads right.

## Drafting a function

Each command works on one interval and needs no build. Deal yourself work with exactly this command, `CARTRIDGE` the cartridge you draft for (`us`), `N` how many functions and `LABEL` the tier label your dispatcher gave you:

```sh
matchkit --version CARTRIDGE next --holding --drafters 1 --per N --route drafter --write --tier LABEL
```

The cartridge is the global `--version`, before `next`; `--holding` takes no value. Add `--function FUNC` to be dealt one named function. Then, for each function it deals:

```sh
matchkit classify FUNC --assignment ID     # what kind of problem it is
matchkit work FUNC --assignment ID         # draft, attach matched context, trial; rerun after each edit
matchkit try --assignment ID artifacts/drafts/FUNC/FUNC.c  # the recorded trial
decomp land submit artifacts/drafts/FUNC/FUNC.c                    # once it is identical
decomp land give-back FUNC --assignment ID --kind drafter --evidence "..." --candidate artifacts/drafts/FUNC/FUNC.c   # to hand it back, in any state
```

`next --write` records an assignment and prints its `id` and, under `close`, every command that works each of its functions: draft, try, then `decomp land submit` once it is identical or `decomp land give-back` to hand it back. The give-back is the one way back and works in any state you stop in: untried with no draft yet, a few trials, a near miss, or the stop. What it records follows from that state: at the stop -- `[stop.draft].trials` (10) recorded `try`s in that assignment, or one identical -- or for a near miss -- a draft whose own trial left only what a search closes -- it records a failed attempt with your closest draft, which `matchkit grind`, the unattended search, deals first; before that it spends no attempt and the function goes back to drafters with your draft and evidence. A run that did not compile or compiled to almost nothing (`NOT COUNTED(try)`) spends no trial. Give `--kind drafter` for C you did not reach or finish (with `--candidate` your closest draft once it has a trial), or `--kind` the route that fixes a function that is not C (`boundary` for a split fragment or an entry into another function, `table` for a name another cartridge's table puts on other code, `merge`, `asm` for hand-written assembly, ...) with `--evidence` what in the words shows it: `next` then deals it on that route only, never to drafters, until its interval changes. `--refused DRAFT.c` keeps a draft the project refused (a fakematch) so no later closest trial stands on it. `try --assignment` judges the draft's note before it spends a trial, as submit does, and prints what submit will say: a draft lands only once it is identical on every cartridge that holds the function, and a function an open assignment holds lands only from a draft tried under that assignment. `next --function FUNC` deals a named function, whatever the band, and refuses one that is queued, assigned or matched everywhere. `next` without `--write` records nothing and deals the same batch again; it says so under `record`. The assignment names the cartridge each function is drafted on, and every command that works one function -- `classify`, `similar`, `m2c`, `work`, `try` and `permute` -- given `--assignment` draws it there, so none of these commands names `--version`. Run without it on a cartridge that lacks the function, each refuses, naming the cartridges that hold it and the command to run.

A function someone already worked is listed under `history`: `given_back` holds every earlier give-back and hand-back with its evidence or note (and its retained draft), and `best_tried` the closest trial any assignment recorded, with its candidate. Start from those rather than from nothing, and do not give it back again for a reason already listed there unless you add what you found. One read off an interval the split has since moved carries `stale` with how it moved: it was about other words, so it neither holds the function back nor counts as a failure. Work given back within `[state].release_cooldown_hours` is dealt after the untried work of its group, and never to the tier that gave it back. A function whose latest drafter got no closer than the closest trial before it, with nothing noted about it since, is at a plateau: `next` deals it to the unattended search, not to drafters (`basis.plateau` names it, why, and what the closest trial's words show).

`work` drafts once into `artifacts/drafts/FUNC/FUNC.c` with m2c, writes the matched functions that resemble it beside it, and trials it on every cartridge; each rerun trials your edited copy and never redrafts. The draft compiles as it stands: what m2c could not type is `M2C_UNK`, and a datum it could not type is reached through `M2C_FIELD(symbol, type *, offset)`. Each callee a matched source defines is declared as that source defines it (a project type as `void *`), and m2c reads its calls by that declaration; a callee no source defines keeps m2c's guess. A float literal is printed as its value; a datum the cartridge's code may write is a variable, not a literal, and is read as one. The values the function loads by address are listed in a comment above it. A draft the compiler still refuses is reported by `work` as `compile-failed`, with the compiler's own words. Replacing `M2C_UNK` and `M2C_FIELD` with real types, from the matched sources `work` lists, is the drafting. A function the assignment lists under `authored` already has a source, identical on the cartridges it names: `work` starts from that source instead, and the work is making it reproduce the others too. `work` records nothing; only `try --assignment` counts a trial against your assignment. `matchkit m2c FUNC --assignment ID` prints the same draft on its own. Each field m2c reads at a constant offset is a field of a struct the draft declares (`FUNC_S1 *arg0`, `arg0->unk10`), at the offset and width it was read: rename the fields and types, never the offsets. A draft that still reads `(T *)((u8 *)p + K)`, which a project may forbid, is rewritten the same way by `matchkit structs DRAFT.c`, and a refusal of that form names the command.

When `try` leaves only register allocation and instruction order -- register-only, reordered and relocation-only words, and no more than 2 words inserted or missing (`[grind].search_gap_words`) -- it prints `NEXT(try): FUNC differs on CART only in register allocation and instruction order, a permute case` followed by the exact search to run: `matchkit --version CART permute DRAFT.c --state DRAFT.permute.json`. Editing registers by hand rarely closes that gap; run that command, port its best output to readable C and `try` that. One `permute` call ends at `[drafting].permute_wall_seconds` (100 s), and that is not the end of the search: the call prints `RESUME(permute): the search is not over` with the exact `matchkit --version CART permute --resume DRAFT.permute.json` that continues it, and the search is over only when it goes `[drafting].permute_stall_seconds` (1200 s) without a new best. If you stop on such a near miss before it matches, hand it back with the `decomp land give-back` command under `close`, its closest draft as `--candidate`: a near miss handed back records a failed attempt, and `matchkit grind` deals those first, at any size, and starts from that draft. `try` also names a comparison the target makes against a constant held in a register (`comparison operand:`) with the C shapes that produce it. Any other difference -- an immediate, a changed or width word, the frame, more words inserted or missing, values bound for another argument register -- is C to change, not a search. So is a difference in relocation-only words alone: nothing moved, so it is the address a name has on that cartridge, and `try` prints `name SYMBOL:` with the address the target reaches. When `try` also prints `table fix:`, the draft is identical once that cartridge's tables place the name where its words reach, and nothing in the C is left to change: `decomp land submit DRAFT.c` queues it with the fix the trial recorded, and the landing writes the table line and proves it by rebuilding. On the reference cartridge, whose names the sources take, it is the source that names what the words reach instead. A line `unreached SYMBOL:` is a name only another cartridge's code uses: write that code under a version condition (`try` shows the `#if` when it can). When you cannot change it, hand the function back with the `decomp land give-back` command the assignment lists under `close`, its evidence naming what is left.

## Landing a function

Check a candidate on its own first. It compiles the one source with the pinned compiler and prints the cartridge's words beside the compiled ones.

```sh
matchkit try --assignment ID FUNC.c   # compile, link and align on every cartridge that shares it
```

A source is not edited into place. It enters through the queue, and `check` refuses any file under `[source].scan` that neither matches its baseline in `data/source-ownership.json` nor carries an event in the queue's ledger.

```sh
decomp land submit FUNC.c                        # queue it, note and all
decomp land status                               # what is queued, what was rejected
decomp land run                                  # place a batch, gate it, record it
decomp land give-back FUNC --assignment ID --kind drafter --evidence "..." --candidate DRAFT.c   # hand it back, in any state
```

`submit` queues a draft only when its recorded trial is identical on every cartridge that holds the function; given several drafts, it queues each one it can and names the rest. `run` holds the landing lock for the whole landing. Each candidate is compiled and compared on every cartridge before anything is built, so one bad candidate is named rather than failing the batch, and a gate refusal that names candidates -- a link naming their objects, a drift interval only they reproduce -- rejects those and lands the rest. A refusal that names none puts every candidate back, and the tree is exactly what it was. Each run writes its own log, `runs/<stamp>-<pid>-<n>.log` under the queue, ending in its verdict; `land status` names the last. A draft submitted again while a landing runs stays queued for the next one.

## What is refused

| Refusal | What it means |
|---|---|
| `HELD(rom-mismatch)` | the rebuilt image differs from the digest its cartridge pins |
| `HELD(realc)` | machine code retyped as data, inline assembly, or padding counted as C |
| `HELD(selection)` | a function claimed as matching that the trial link does not reproduce |
| `HELD(readme-stale)` | README.md no longer agrees with a live measurement; run `make readme` |
| `HELD(development-stale)` | this file no longer agrees with the description; run `make development` |
| `HELD(setup-toolchain)` | a supplied file whose digest is not the one pinned for its name |
| `HELD(source-ownership)` | a source edited into place rather than landed through the queue |

None of these is advisory. The build stops, names what it refused, and leaves nothing half-written behind.
